Run a focused regression before choosing the wider checks for your change.

```i test stdout=exact package=checks title="test/bool_test.i"
(
	testlib = (test) = i/test
	i/bool
)

test("negation", () { assert(bool.not(True) == False) })
```

```text
pass checks/bool_test.negation
1 passed, 0 failed
```

The docs runner supplies the manifest and compares this transcript at O0/O2. Repository commands below run from the root; `I=target/release/i` selects an existing CLI.

## Setup

[Development setup](https://github.com/nmnmcc/i/blob/main/docs/development.md) uses `git submodule update --init crates/ilang-binaryen/binaryen`, then `devenv shell`. The pinned shell supplies the toolchain, command runtimes, CMake, Wasmtime, wasm-tools, and matching Playwright browsers. Binaryen is built from source and linked into the CLI; its first build takes minutes, later builds reuse it.

CI builds with `cargo build --release --locked -p ilang-cli`. Shared redesign worktrees route Cargo work through the heavy queue described in [testing.md](https://github.com/nmnmcc/i/blob/main/docs/testing.md).

## Check selection

These commands are defined in [checks](https://github.com/nmnmcc/i/blob/main/scripts/checks) and [CI](https://github.com/nmnmcc/i/blob/main/.github/workflows/ci.yml).

The whole workflow is called CI; each of its jobs is named only by what it runs (`build (…)`, `lint (…)`, `test (…)`, `run (…)`, `corpus (…)`, `docs (…)`); the local entry is `scripts/checks`; and the smallest runnable unit (one Cargo target, one shard) is called a test set. Do not use one word for more than one of these layers.

Product name: `The i Programming Language` when it stands alone (title, start of sentence, name fields); `the i Programming Language` mid-sentence; otherwise `i`, always lowercase. Check with `git grep -in 'i programming language'`: every hit must be one of those two forms.

| Change | Command or part |
| --- | --- |
| Checker | `cargo test -p ilang-check --locked` |
| One spec case | `cargo test -p ilang-cli --test spec --locked -- a1_entry_exports` |
| Source formatting | `"$I" fmt --check lib stdlib bench examples` |
| Compiler formatting/lint | `cargo fmt --all -- --check`; `cargo clippy --workspace --all-targets --locked -- -D warnings` |
| Snippets | `scripts/check-snippets`; `python3 -I scripts/check-snippets-test` |
| Runtime smoke | `./scripts/wasi-smoke "$I"` |
| Generated models | `./scripts/test-generation --mode short --binary "$I"` |
| Corpus shard | `CHECKS_SHARD=K/N ./scripts/checks i`, or `./scripts/review-corpus run --binary "$I" --shard K/N --jobs 4` |
| SDK/browser checks | `./scripts/checks js` |
| Editor checks | `./scripts/checks editors` |

`rust-lint` runs formatting, lint, and snippets; `rust-test` runs the tests; `rust` combines them. Other accepted parts are `snippets`, `i`, `js`, `editors`; no argument selects `rust i js editors`. The `i` part tests `stdlib`, `examples/hello`, and `bench` at O0/O2, then smoke, corpus, and generated models. Smoke covers Wasmtime and Node; generated failures retain source/observations.

`CHECKS_TEST_GROUP=targets` with `CHECKS_TEST_TARGETS="ilang-check:lib ilang-cli:http"` makes `rust-test` run exactly those Cargo targets: `lib`, `bin`, `doc`, or a file of the crate's `tests/`, one `cargo test --no-fail-fast` per crate in the order given. This is how a planned test shard runs. The hand-written groups (`check-heavy`, `check`, `spec`, `spec-K/N`, `cli-heavy`, `cli`, `rest`) still work. `CHECKS_SHARD=K/N` makes the `i` part run shard K of N of the review corpus instead of all of it, and `CHECKS_SKIP_CORPUS=1` leaves the corpus out. `CHECKS_BUDGET` (seconds, default 270) is the shard budget handed to the shard tooling.

## CI

Every push to main runs the full gate. A pull request runs the same gate except for the jobs whose inputs did not change (Rust, docs, editors); `summary (required)` lists what ran and fails if a planned job did not report. The wall time of a run is in its job summary. When a run fails, open the first red job in the summary and start there.

The slow sets are split into shards by `i-shard` (`crates/ilang-shard`), so no shard list is written by hand. The units of a set (test targets, spec cases, corpus cases, projects) are its sorted keys, and their costs come from [ci/costs.json](https://github.com/nmnmcc/i/blob/main/ci/costs.json); a unit without a cost takes the median of its set. The shard count is `ceil(total / budget)`, raised one at a time while a shard without an over-budget unit would still go over the budget, and the units are packed longest first onto the least loaded shard. The plan prints every unit that is over the budget on its own and every unit that took the median. A stale table changes only how evenly the shards are loaded, never which units run. Refresh it from CI logs with `scripts/ci/refresh-costs --logs <dir>`, and after adding or removing units with `--sync-keys`.

## Documentation checks

From `docs`, run `npm ci`, `npm run build`, `npm run check:placeholders`, `npm run check:links`, `npm run check:rendering`, and `npm run check:examples`; [package.json](https://github.com/nmnmcc/i/blob/main/docs/package.json) defines them. Set `I_BIN` to an existing compiler and `I_SNIPPET_PARSER` to a matching prebuilt parser to avoid builds.

## Corpus records

Projects such as [review-native/fake](https://github.com/nmnmcc/i/blob/main/tests/review/cases/review-native/fake/i.toml) keep `i.toml`, `src/main.i`, and `expected.json` together. Observations include compiler identity, `check --types`, and test/main O0/O2 results. `manifest.json` records origins/rules; `inventory.json` accounts for occurrences; `requirements.json` independently records defects and required behavior. Resource caps are not performance guarantees; censored timeouts do not establish termination. Change expectations with the requiring spec paragraph, review semantic requirements independently, and promote fixed failures; [testing.md](https://github.com/nmnmcc/i/blob/main/docs/testing.md) documents regeneration.

Running every check can be long; the repository gives no general memory estimate.
