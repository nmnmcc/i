Connect your editor to diagnostics, completion, navigation, and formatting.

```sh
scripts/dev-editors
```

Open the i source folder in your editor and run this in the development shell. The command builds `target/release/i`, installs the VS Code client dependencies, links its extension, and prepares Zed's development extension. It refuses to overwrite an existing VS Code extension; reload the window after linking.

## Zed extension

Choose **extensions: install dev extension** and select the printed `target/editor-dev/zed` directory. The extension toolchain needs `wasm32-wasip2`; Zed downloads wasi-sdk for its parser or uses `WASI_SDK_PATH`.

```sh
scripts/dev-editors zed
```

Commit grammar changes before this command: Zed checks out the recorded revision. Rebuild the development extension in Zed afterward.

## Compiler location

```sh
i lsp
```

The server communicates over standard input and output. VS Code's `ilang.path` defaults to `i` on `PATH`; it accepts an absolute path or one relative to the first workspace folder. Zed's supplied setting uses `target/release/i`; for another project, omit `lsp.ilang.binary.path` to use `PATH`, or set an absolute path.

## Editor features

Both editors highlight `.i`; VS Code also supplies bracket matching, indentation, and comment toggling. Zed does not register `.is` files. The supplied settings enable formatting on save; the server also provides hover, references, and rename. The grammar and highlight queries live in `editors/tree-sitter-i`; semantic checks come from the server.
