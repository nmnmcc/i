A service supplies operations that a function needs from its caller. This page shows how to take and provide services, replace one in a test, and handle expected failures. It builds on [functions and branches](/docs/tour/functions-and-branches) and [types and inference](/docs/tour/types-and-inference).

```i run package=tour title="src/main.i"
(
	(Io) = i/io
)
main = () <- (io : Io) { io.print("hello") }
```

```text
hello
```

## Taking and providing services

A service is an ordinary labelled value, usually a record of functions. `Io` is defined in `i/io` with a `print` function. The head `<- (io : Io)` takes that service and gives it the local name `io`. The function's type is `() <- (Io) -> Nil`: parameters, need, then result. `io.print` writes its string and a line feed.

`main` in `src/main.i` is the default program entry. `i run` provides the native platform services, including `Io`, assertions, a top-level failure handler, and the task scheduler. Your own services must be supplied by your program. Importing a service type makes its name available; it does not create an implementation.

A need is the intersection of its service requirements. A function that uses two services needs both. Entries are keyed by their type constructors, so their order does not matter. The name `io` is local to the function; callers provide an `Io`, without a label called `io`.

For the next examples, use a package named `tour`. Define your own service in `src/greeting.i`:

```i file=src/greeting.i title="src/greeting.i"
(
	Greeting(..)
	message
)
Greeting = (read = () -> String)
message = () <- (g : Greeting) -> String { "hello, " <> g.read() }
```

Then provide an implementation at the call:

```i run package=tour title="src/main.i"
(
	(Io) = i/io
	(Greeting, message) = tour/greeting
)
main = () <- (io : Io) {
	io.print(message() <- (Greeting(read = () { "reader" })))
}
```

```text
hello, reader
```

`message` has type `() <- (Greeting) -> String`. The expression after `<-` supplies the service for that call. The service's function returns a string without needing another service. Providing at a block supplies every call in that block; an inner provide replaces an outer service of the same type. Unreplaced requirements still come from outside.

A function that calls `message` also needs `Greeting`, unless it provides one. That requirement is inferred even when its head has no service pattern. A zero-argument function is a computation you can save and call later; its services come from the place of the call.

## A second implementation for a test

Use the same `src/greeting.i` above. Here it is attached again so this test is a complete example:

```i file=src/greeting.i title="src/greeting.i"
(
	Greeting(..)
	message
)
Greeting = (read = () -> String)
message = () <- (g : Greeting) -> String { "hello, " <> g.read() }
```

```i test package=tour title="test/greeting_test.i"
(
	testlib = (test) = std/test
	(Greeting, message) = tour/greeting
)
test("a fake greeting", () {
	assert({ message() <- (Greeting(read = () { "test" })) } == "hello, test")
})
```

The fake is another value of `Greeting`. The application function needs no testing switch. `test` comes from `std/test`; [macros](/docs/tour/macros) explains how it registers the test. The project needs `std` and `[test] collection = "std/test.tests"` in its manifest.

The checker rejects a function promised to need nothing when its body leaves a service unsupplied:

```i error E0501 package=tour title="src/main.i"
Greeting = (read = () -> String)
message = () <- (g : Greeting) -> String { g.read() }
main : () -> String = () { message() }
```

The real diagnostic is: `` `Greeting` is not a subtype of `Never` `` (E0501). The annotation on `main` promises no need. Provide a `Greeting` inside it, or allow the service in the function's type and supply it at a caller.

## Errors and missing values

On this tree, `Fail(E)` and `i/fail` support raised errors, but standard-library APIs have not all changed to that form. For example, `std/int.parse` returns `Result(Int, Nil)`. `Result` is a built-in union with `Ok(value)` and `Error(error)`. `Option` comes from `std/option`, with `Some(value)` and `None`; `std/list.first` returns one.

```i run package=tour title="src/main.i"
(
	i/fail
	i/core
	(Io) = i/io
	std/int
	std/list
	std/option
	std/result
)
main = () <- (io : Io) {
	io.print(
		core.inspect(int.parse("42")),
	)
	io.print(
		core.inspect(int.parse("oops")),
	)
	io.print(
		core.inspect(list.first([7, 8])),
	)
	empty : List(Int) = []
	io.print(
		core.inspect(list.first(empty)),
	)
	io.print(
		core.inspect(
			option.to_result(list.first(empty), "empty"),
		),
	)
	io.print(
		core.inspect(fail.catch(() { result.to_error(int.parse("oops")) })),
	)
	io.print(
		core.inspect(fail.catch(() { fail.raise("bad input") })),
	)
}
```

```text
Ok(42)
Error(Nil)
Some(7)
None
Error("empty")
Error(Nil)
Error("bad input")
```

Match these values with the branches introduced earlier. `option.to_result` chooses an error for absence. `result.to_error` turns an `Error` into a raised error; `fail.catch` runs a computation and returns its success or raised error as a `Result`. `fail.raise` ends the current computation through its `Fail(E)` need. An error can be any value, including a string. Catching supplies the handler rather than changing every called function.

An assertion failure reports a programming mistake through the separate `Assert` service. A **stop** terminates execution, for example after `panic` or invalid use of a continuation. A stop is not an error and is not caught by `fail.catch`. An unhandled raised error reaching the program entry also terminates the program.
